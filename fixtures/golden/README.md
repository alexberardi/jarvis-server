# Golden fixtures

Byte-exact outputs captured from the legacy Python implementation. Go code must reproduce them
exactly (PLAN §4). They are generated, never hand-edited.

## prompts/ (G1 + G5, docs/cc/03 §9)

Generated by [`tools/golden/export_prompts.py`](../../tools/golden/export_prompts.py), which
imports command-center's real prompt providers and calls the real
`ConversationHandler._get_system_prompt` wrapper. The exporter lives here, not beside the Python
code, because the Python server repos are frozen.

Regenerate:

    ../jarvis-command-center/.venv/bin/python tools/golden/export_prompts.py \
        --cc ../jarvis-command-center --out fixtures/golden/prompts

| File | Contents |
|---|---|
| `<Provider>__<case>.json` | `messages[0]` (`system_prompt`), `user_message_suffix`, `response_format`, and for native providers `native_tools`. `inputs` records the node context, tool set name and command flags. |
| `_inputs.json` | The named tool sets (`none`, `client`, `server`, `all`, `node_dev`), personas and DT_KEYS used by the cases. |
| `_blocks.json` | Per-turn blocks (speaker, unknown speaker, ambient, personality reminder, characterization) and every string constant in `core_rules`. |
| `_parse.json` | G5: `parse_response` and `sanitize_text` for each provider over `tools/golden/inputs/parse_corpus.json`. |
| `_index.json` | SHA-256 of each `system_prompt`, for a quick drift check. |

Providers: `Qwen3_14B_Compressed` (prod), `Qwen3_8B_Compressed` (dev), `Qwen3_5_9B_Compressed`,
`ChatGPTOpenAI` (e2e). Inputs: synthetic edge cases in `tools/golden/inputs/corpus.json`
(`_refinable` params, non-ASCII, `<`, `&`, nested arrays, date-time params, HA agents small/big/
sensor-only, room hierarchy) plus `node_dev`, the real built-in command set captured from the dev
node container.

Known intentional divergences (decisions in docs/cc/QUESTIONS.md):

- D8 bug fixes that change bytes: the `<message>` unwrap is added to the 8B/9B sanitize (D22), so
  `_parse.json` rows for those providers with `<message>` input are expected to differ.
- The native path gets the text path's per-household server-tool gates (D22); fixtures here use
  the ungated legacy tool lists, so gated Go output is compared against the matching tool set.

Not yet covered: G2/G3 date context and resolution (regenerated from the corrected spec, D8),
G4 ISO guard, the recently-shown block.

## dates/ (G2 + G3, legacy reference)

Generated by [`tools/golden/export_dates.py`](../../tools/golden/export_dates.py) with the clock
frozen at 12 instants (every weekday, month and year end, Feb 29, both US DST transitions) and six
zones (`UTC`, `America/New_York`, `Asia/Kolkata`, `UTC+05:30`, none, invalid):

    TZ=UTC ../jarvis-command-center/.venv/bin/python tools/golden/export_dates.py \
        --cc ../jarvis-command-center --llm ../jarvis-llm-proxy-api --out fixtures/golden/dates

**These are the legacy outputs, bugs included.** Go fixes the date bugs (D8, docs/cc/03 §8.1–8.6),
so the Go golden for those cases is the corrected spec, and these rows document what changed.
Bugs visible in the data:

- Time modifiers resolve in UTC, not local time: `["tomorrow", "morning"]` in New York gives
  `T07:00:00Z` (03:00 local) and a separate midnight instant for "tomorrow".
- An invalid zone (`Not/AZone`) raises `UnknownTimeZoneError` instead of falling back.

| File | Contents |
|---|---|
| `vocabulary.json` | The 64 static DT_KEYS (llm-proxy `ALL_DATE_KEYS`, sorted). |
| `date_context.json` | `generate_date_context_object` per instant × zone (or the error raised). |
| `resolution.json` | `resolve_date_keys` for every key, `in_*` forms and combinations, per instant, UTC and New York. |
| `normalize.json` | `normalize_date_key` samples. |
