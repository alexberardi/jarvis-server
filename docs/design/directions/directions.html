Mockups: A · HearthB · Quiet VioletC · Ledger

Jarvis Automation: three visual directions

For the design audit (docs/design/AUDIT-2026-10.md, item #331). Static mockups of Dashboard and Chat with the seeded household's people and rooms; the content is the same in all three so only the design differs. Every colour pair is checked against WCAG AA in both themes (the tables under each direction). System fonts only; this page fetches nothing.

All three fix the audit's systemic problems the same way: one token set with status colours, shared Button / Card / Chip / Field components, focus rings, skeleton and error states, and the motion rules below. They differ in feel, colour, shape and density. Pick one, or a mix (for example B's colours with C's dashboard layout).

Motion

  • Press: scale(0.97), 120ms, ease-out. Hover: background colour only, 150ms ease.
  • Menus and popovers: opacity + scale(0.97 to 1) from the trigger, 180ms, --ease-out.
  • Drawer and sheets: translateX/Y, 260ms, --ease-drawer; closes 200ms.
  • New chat message: opacity 0 to 1 and 4px rise, 180ms, the newest only (never the history).
  • Loading: static skeletons in the card's shape; a spinner only inside a pressed button.
  • prefers-reduced-motion: every transform dropped; opacity fades of 120ms or less remain.

Curves (Emil): --ease-out: cubic-bezier(0.23,1,0.32,1), --ease-drawer: cubic-bezier(0.32,0.72,0,1). Nothing over 300 ms; no animation library.
