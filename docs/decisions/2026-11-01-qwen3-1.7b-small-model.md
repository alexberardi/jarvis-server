# Qwen3 1.7B is the catalog's small model; Llama 3.2 1B is not added

- **Date:** 2026-11-01 (user: "try qwen 1.7B. that's a good middle ground")

Low-end PCs need a live model that fits a small GPU. `scripts/toolbench` (86 cases: the desktop
toolset's examples plus the single-turn scenarios, replayed with jarvisd's real prompt and tools)
on this devbox's CPU gave:

| Model | Tool calls | Right tool | Tool + args | Home (13) |
| --- | --- | --- | --- | --- |
| Llama 3.2 1B Q8_0 | native | 10.5% | 9.3% | |
| Llama 3.2 1B Q8_0 | text, Qwen3_8B_Compressed | 39.5% | 27.9% | 10 |
| Qwen3 1.7B Q8_0 | native | 72.1% | 58.1% | 11 |
| Qwen3 1.7B Q8_0 | native, Qwen3_8B_Compressed | 68.6% | 57.0% | 11 |
| Qwen3 4B Q4_K_M | native | 62.8% | 54.7% | 10 |
| Llama 3.2 3B Q4_K_M | native | 74.4% | 61.6% | 9 |

Rows without a prompt used Cloud (the sandbox's remote-model prompt); thinking was off.

- **Llama 3.2 1B is not added.** llama-server's parser rejects its native tool calls (39 HTTP
  500s), and in text mode it mostly describes an action instead of calling a tool ("Steam has
  been launched"), which is worse than a wrong call on a speaker.
- **`qwen3-1.7b` (Q8_0, 1.8 GB) is added** with the qwen3-4b settings (Qwen3_8B_Compressed,
  qwen3.jinja, thinking switch). It scores at or above the 4B on the same prompt at under half the
  size. Recommend picks it where it fits and the 4B is only tight: an 8 GB Mac and a 6 GB card,
  which used to get the 4B.
- A 4 GB card still fits neither at the 16k default context (the 1.7B needs about 4.2 GB). A Q4
  file or a smaller default context are the levers if 4 GB cards matter; neither is benchmarked.
