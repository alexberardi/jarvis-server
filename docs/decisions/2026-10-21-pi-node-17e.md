# Pi node 17e: wake greeting, maintenance restart, ACT-LED fallback

- **Date:** 2026-10-21 (build agent, loop #427; the last slice of
  [the music-ducking split](2026-10-19-pi-node-music-ducking.md))

Choices made porting `N:core/wake_response.py`, `N:services/maintenance_restart_service.py` and
`N:services/led_service.py` to the Go Pi node:

- **The greeting lives in memory, not on disk.** One `*greeting` (PCM, rate, channels) per
  pipeline, fetched at start and after each turn, used once. A restart's first wake plays the
  chime. N:'s bundled `sounds/wake/*.wav` tier is the synthesised chime here, and its last tier
  (TTS "Yes?" on the wake path) is dropped: jarvisd's `/wake-response` already answers "Yes?" when
  the model can't, and rendering on the wake path is the latency the cache exists to avoid.
- **No pre-roll under a greeting.** The chime path keeps up to `PreRollSecs` of what the mic heard
  and mutes the chime's tones (#358); a spoken greeting is a voice whisper would write down, so
  after a greeting nothing heard while it played is kept and the first two chunks are zeroed.
- **Pi profile only** (`voice.Config.Greeting`), gated by the chimes (`wake_ack_audio_enabled`).
  The desktop agent keeps the chime: a model call per turn there was not asked for.
- **Maintenance restart guards N: lacks.** A process started after today's restart time does not
  restart for it (systemd's `RestartSec=5` brings the node back inside the same minute, and N:
  would exit again until the minute passed), and the RSS ceiling only fires after an hour up (a
  ceiling under the baseline loops every poll into the unit's `StartLimitBurst=10` in 30 min; N:'s
  2026-08-03 kitchen-node loop). Both keep one exit per trigger, so the start limit is never near.
- **No silent-restart marker.** N: writes `.pending_maintenance_restart` so its boot warmup stays
  quiet; the Go node says nothing on boot (row 23, "drop"), so there is nothing to silence.
- **Ceiling semantics follow N:.** Unset is `max(320 MB, 35% of MemTotal)`, `0` turns the ceiling
  off, and the snapshot reports the ceiling in effect.
- **ACT LED as an output of the same `hat.LEDs`.** The two-layer model, previews and
  enable/disable are shared; the ACT output remaps patterns as N:'s `_effective_pattern` does,
  blinks alert / error / shutdown_warning at N:'s periods, blinks the Go node's setup mode slowly
  (1.5 s), and gives the LED back to the trigger it found (`mmc0`, `actpwr`, …) instead of N:'s
  `default-on`. The directory is probed as `ACT`, then `led0` (older kernels). Raspberry Pi OS's
  `99-com.rules` lets the `gpio` group write it; `install-pi.sh` is unchanged.
