# SIP L1 lane: how it copies FreePBX, and what it plays rather than runs

- **Date:** 2026-10-21 (agent, building piece 1 of the phone-over-SIP plan, loop item #442)

The L1 lane of [../cc/phone-sip.md](../cc/phone-sip.md) §5 is `test/sip/`, `scripts/sip-lane`,
`scripts/sandbox up --sip` and `tools/siplane`. The choices a later reader would otherwise
rediscover:

**Images.** Asterisk is `andrius/asterisk:22` pinned by digest (22.11.0, the Asterisk FreePBX 17
runs), plus the English core prompts (`asterisk-core-sounds-en-ulaw-1.6.1`, pinned by sha256),
since the image ships no sounds. FreePBX installs the extra sounds too; the lane uses
`please-try-call-later` (core) where FreePBX plays `pls-try-call-later` (extra): same words.
The far ends are one image on `debian:trixie-slim` pinned by digest with trixie's
`baresip-core` (1.1.0), `sip-tester` (SIPp 3.7.3) and `sox`. The Debian packages follow trixie
point releases; pinning them by version would break when the archive drops the old ones.
Both are built locally, tagged by a hash of their directory, never pushed.

**Configuration is written, not generated.** `pjsip.conf` is laid out the way FreePBX 17's
`PJSip.class.php` writes it (endpoint + aor + auth per extension, every field spelled out, no
templates) with the defaults jarvisd must survive marked; a Go test
(`TestLaneCopiesFreePBXDefaults`) keeps them, and the `registered` scenario checks the running
PBX shows them. Whether these still match a real FreePBX is L2's job (diff
`pjsip show endpoint`), weekly.

**The carrier's answers are dialplan, not a carrier.** Busy (486), no answer (183 + announcement
+ 503) and all trunks busy (200 + recording) are fixed numbers in `extensions.conf` running the
applications FreePBX's `macro-dialout-trunk` / `macro-outisbusy` run when the trunk says so.
One fake carrier (baresip, the `carrier` trunk) cannot answer differently per number, and what
jarvisd sees is the same: the PBX's response, not the carrier's.

**Responsive Firewall stand-in.** Asterisk has no firewall. `lane-firewall` (in the Asterisk
image) reads Asterisk's security log and, after 3 failed authentications from one address, adds
it to a pjsip ACL; the PBX then refuses that address with **403**. The real firewall **drops**
packets (the client sees timeouts) and bans for 30 minutes or more; the lane answers 403 and
keeps the ban until `scripts/sip-lane unban`. What jarvisd must do is the same (stop after 3
failures, say so); a client that only handles timeouts would pass L2 and fail here, or the other
way round, so the SIP client should treat both as "blocked". The ban test registers from
127.0.0.66 (any loopback address but 127.0.0.1 works) so the far ends on 127.0.0.1 keep going.

**Everything on loopback, host networking.** Asterisk binds 127.0.0.1 only; ports are
5060/20000+ plus the sandbox's offset, so lanes of parallel sandboxes do not collide. Far ends
are long-running baresip processes driven over `ctrl_tcp` (dial, events), with fixed WAV paths:
the runner rewrites `say.wav` before a call and transcribes `heard.wav` after it. baresip hangs
up when its WAV ends, which is how a call's length is set.

**Transcription.** What a far end heard goes to the sandbox's CPU whisper (`--voice`,
whisper-small.en, the harness default) through the node media API, upsampled to 16 kHz; it must
match what was said with a word error rate of at most 0.25 **within** the recording
(`wordErrorRateWithin`: the PBX's own prompts around it, e.g. the echo test's 22 s
instructions, are not errors). CI uses the same model as the dev box rather than a smaller one,
so a pass means the same thing in both.

**SIPp needs a nonce.** In a container SIPp's pid is 1, so its default Call-ID, From tag and Via
branch repeat across runs, and Asterisk drops the next run's INVITE as a retransmission of the
last dialog. The runner passes `-cid_str` and `-key run <nonce>`, and the scenarios put `[run]`
in their branches and tags.

**No jarvisd yet.** Extension 100 is the Jarvis extension; until the SIP provider can register
(piece 2), a baresip stand-in holds it (`max_contacts=1`: jarvisd and the stand-in cannot both
register; piece 2 decides how the lane hands 100 over).
