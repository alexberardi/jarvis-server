- **Date:** 2026-10-13
- **Moved from** the STATUS.md decision log on 2026-10-14.

**Dictation on the user's Hyprland: keys on the desktop's layout** ([agent/DESIGN.md §14](../agent/DESIGN.md) "The keymap follows the desktop's layout", Evidence "Hyprland: dictation typed nothing"). Two voice dictations reported success and typed nothing. Reproduced in a nested headless Hyprland 0.56.2 with the user's own Lua config and fcitx5: (1) XWayland windows read virtual-keyboard keycodes with the desktop layout, not the uploaded keymap, and the old keymap put text on keycodes 9, 10, 11… (Escape, 1, 2…): a GTK dialog was cancelled, `success: true` (the user's front window is the Android Emulator, XWayland); (2) with a Lua `hyprland.lua`, `hyprctl dispatch focuswindow address:…` is a Lua syntax error, so every named app was `focus_failed`. Fixed: the virtual keyboard reads the compositor's layout (`wl_keyboard.keymap`) and presses each character on its own keycode (Shift for level 2), others on keycodes the layout leaves empty; the keyboard is activated before its first key; XWayland + characters off the layout → `unsupported_characters`, nothing typed; `hl.dsp.focus` fallback; unnamed typing names the front window (`into`, `front_app`) and refuses when no window has focus (`no_focused_window`); a 0.1.0 extension's `unknown_command` for fill/click → `extension_outdated` with "update the Jarvis browser extension". Hyprland permissions are off on the user's box: no `hyprland.conf` change.
