Cross-module FKs are deliberately not introduced: modules migrate and import independently.

## Type notes

- Ids are `varchar(36)` UUIDs generated by the app (`uuid4`) → TEXT PRIMARY KEY, no default.
- All timestamps were naive `timestamp` written with `datetime.utcnow` (UTC). Stored ISO-8601 UTC.
- `data`, `metadata_json` were already JSON-in-TEXT.
- booleans → 0/1.
- **ORM-side defaults promoted to DB defaults:** `is_active` 1, `is_read` 0, the three counters 0,
  `delivery_status` 'pending'. Legacy had them only in SQLAlchemy.
- `device_type` (`ios`/`android`), `target_type` (`user`/`household`) and `delivery_status` were
  free strings; no CHECK added, values are only documented in comments.

## Dropped

`alembic_version`. Nothing else. (No settings table existed; the service had no settings definitions.)

## Legacy-import notes

- Copy rows 1:1; reformat timestamps as ISO-8601 with `Z`.
- `inbox_items` with `category = 'adapter_proposal'` reference the cut LoRA pipeline
  (docs/cc/00-platform.md row 12): they become inert. Import them or skip them; either is safe.
- `notification_log` is an audit trail; importing it is optional.

## Setting keys

None. jarvis-notifications had no `settings_definitions` and no settings table.
